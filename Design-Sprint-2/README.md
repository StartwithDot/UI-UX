# Design Sprint 2: Research and Problem Framing

**Weeks 5 to 8. UX1 to UX5.**

The project: a **government skill training scheme has a 60 percent dropout rate between enrolment and first class**. Nobody knows why. There is no interface to redesign yet, because the problem has not been found.

This sprint is the one that separates designers who decide from designers who decorate. There are no screens for the first two weeks.

## What ships by week 8

- 5 interviews per designer, recorded with consent, transcribed, tagged
- One usability test on the existing enrolment portal, 5 participants
- A card sort and a tree test on the scheme's information structure
- A findings document where every finding names its source and its confidence
- One assumption tested with a designed probe, not an opinion
- An opportunity solution tree
- A redesigned enrolment flow that answers the researched problem, not the assumed one
- A research repository another designer could pick up cold

## The hard rule of this sprint

**Every finding names the participant, the task, and what they did.** "Users found it confusing" fails review, every time, without exception. Confidence must be labelled: high if three or more participants did it, medium if two, single observation if one, and a single observation is still worth recording as long as it is labelled.

## Carried forward from Sprint 1

The shared design system in `../Design-Sprint-1/system/` is now the cohort's system. It continues here. Components get added when the research demands them, and every addition needs the finding that justified it.
