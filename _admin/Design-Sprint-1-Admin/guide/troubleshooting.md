# Troubleshooting

Failure modes seen, and what to do.

| Situation | Do this |
|---|---|
| A designer opens Figma on Day 1 of week 1 | Do not say stop. Say "show me your problem statement first." |
| Critique turns into taste | Stop. Read the rubric aloud. Restart. Every comment names a principle and a user cost. |
| The shared system is blocked | Pair with the system owner at once. A blocked system blocks five people. |
| The cohort converges on the same design | Give each a different constraint card for one round. |
| Someone has made no pull request by Day 4 | Ask what is blocking them, privately, before the week closes. |
| Participants cannot be recruited | Switch method, reduce n, state the limitation in writing. This is sprint content. |
| Nobody disagrees in critique for two sessions | Name it: "nobody has disagreed in ninety minutes, which means either everything is good or nobody is saying." |
| A designer fakes a gate (uniform passes, no measured numbers) | Send it back with one instruction: "give me the ratio." |
| An AI footer is missing or the log does not match | Ask the designer to walk through the prompt live. |
| An external reviewer is harsher than you are comfortable with | Do not intervene. Debrief afterwards. |
| A designer receives "Not yet" and spirals | Meet within 48 hours with the written list of next steps, and a first action for the next seven days. |
| A designer is over 24 hours a week for a fortnight | The week is mis-sized. Fix it for everyone, not just them. |
| A designer withdraws | Record why, honestly, in the retro. Do not redistribute their role load without telling the cohort. |
