## Sprint folders

Every sprint has the same files, numbered the same way.

```
Design-Sprint-1/
  00-READ-FIRST.md         what ships, how the 4 weeks run
  01-project-brief.md      the client, the users, the constraints
  02-week1.md              week 1, day by day: learn then do
  03-week2.md
  04-week3.md
  05-week4.md
  06-accessibility-gate.md the checklist that blocks sign-off
  07-critique-guide.md     how critique is run
  08-glossary.md           every term used in this sprint, defined
  students/UX1..UX5/       your work
  system/                  the shared design system
  delivery/                shared client-facing output
  fundamentals/            learning summaries, teardowns, drills
```

| Sprint | Weeks | Focus |
|---|---|---|
| `Design-Sprint-1` | 1–4 | Visual craft and one complete flow |
| `Design-Sprint-2` | 5–8 | Research and problem framing |
| `Design-Sprint-3` | 9–12 | Product thinking and metrics |
| `Design-Sprint-4` | 13–16 | Design systems and handoff |
| `Design-Sprint-5` | 17–20 | Complex interfaces and AI |
| `Design-Sprint-6` | 21–24 | Ship, measure, and tell the story |

`Design-Sprint-N-Admin/` folders are private. They hold model answers, rubrics, and the injected failures. Not for designers.

## How a day works

```
MORNING — LEARN, 1 to 2 hours
  a named chapter, a named video, a named page
  → commit students/UX{n}/week{n}/day{n}-learning.md

AFTERNOON — DO, 1 to 2 hours
  a task that uses exactly what you just learned
  → commit students/UX{n}/week{n}/{TASK-ID}-{name}.md
```

Learning comes first, every day. Every task tells you what to learn before it, gives you the method, shows you a worked example, and states when you are done.

## Cohort

5 designers, coded UX1 to UX5. No real names in the repositories.

Two roles rotate weekly: **critique lead** and **system owner**. Everyone holds each role at least once per sprint.
