# DOTSET Design Program

Product design cohort. 5 designers, 6 sprints, 24 weeks.

## What is in this folder

| Folder | Purpose | Who reads it |
|---|---|---|
| `Design-Sprint-1` to `Design-Sprint-6` | Public sprint repos. Briefs, task lists, student folders, shared system and delivery zones. | Everyone |
| `Design-Sprint-1-Admin` to `Design-Sprint-6-Admin` | Private admin repos. Review notes, question banks, failure injections, critique keys. | Core admins only |
| `UIUX Program Skeleton.md` | The field map. What product design is in 2026, every foundation area, tools, resources. | Everyone, read first |
| `Learning Resources.md` | The full resource index. Books, courses, free references, mapped to sprint and week. | Everyone |
| `Program Structure.md` | How the program operates. Sprint shape, roles, zones, gates, assessment, calendar. | Everyone |

## Read in this order

1. `UIUX Program Skeleton.md` for the field
2. `Program Structure.md` for how this cohort runs
3. `Design-Sprint-1/README.md` for the current sprint
4. `Design-Sprint-1/docs/student-guide.md` for daily working rules
5. Your own `Design-Sprint-1/students/UX{n}/week{n}/problem_statement.md` for the tasks

## The six sprints

| Sprint | Weeks | Theme | Ships |
|---|---|---|---|
| 1 | 1 to 4 | Craft and the single flow | One rebuilt high stakes flow, all states, accessibility passing |
| 2 | 5 to 8 | Research and problem framing | Real discovery with 5 interviews and a usability study |
| 3 | 9 to 12 | Product thinking, end to end feature | A scoped feature with metrics, IA, tested prototype |
| 4 | 13 to 16 | Design system and engineering handoff | Tokens, components, one component in code, governance |
| 5 | 17 to 20 | AI surfaces and dense enterprise UI | An AI feature with full failure states, one dense workflow surface |
| 6 | 21 to 24 | Ship, measure, portfolio | Live instrumented surface, measured outcome, 3 case studies |

## Cohort

5 designers, coded UX1 to UX5. No real names in the repos.

Two rotating positions each week: critique lead and system owner. Everyone holds each position roughly twice per sprint. Details in `Program Structure.md`.
